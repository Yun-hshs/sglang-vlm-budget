# GPU 服务器接入与验收

单卡服务、CPU 测试和两条静态图冒烟已通过。当前部署参数和实际视觉 Token 见[部署验收](DEPLOYMENT_SMOKE.md)。下面的流程用于准备正式实验，其中仍需覆盖多轮、OCR、异常处理和缓存接口。新环境应记录 GPU、驱动、CUDA、系统与存储，凭据通过安全渠道提供。

1. 选择经当前官方说明核实的 SGLang 发行版，固定模型 commit 与 BF16；修改 configs/model.yaml。保存服务完整启动命令。
2. 安装客户端与服务端依赖，分别保存 pip freeze。运行 CPU pytest 并保存日志；失败先修复，不跳过后声称成功。
3. 核对启动参数与 /v1/chat/completions 流式 usage、finish_reason、/flush_cache 行为。记录未支持字段。
4. 运行 5 样本端到端冒烟：单图/多轮/OCR/图表/异常处理。每轮确认图片确实进入请求，答案来自模型。
5. 按任务准备获准固定子集。相同子集跨策略复用；真实多图子集没有就记录缺失。使用官方 evaluator 复核评分。
6. 各任务独立跑实验 A/B，Warm 与 Cold 分开。先单并发再增加，记录失败、OOM 和输出截断；不擅自删去失败配置。
7. 每组独立采 GPU 设备内存，标注采样周期和基线；需要进程真实峰值时补服务 profiler。对视觉 Token 在处理器端接入实际网格数据。
8. 原始 JSONL → summary.csv → 图表；检查口径后补报告和答辩中的待验证页。不得覆盖历史 run 目录。

验收完成必须提供真实模型回答证据、测试日志、版本锁、数据来源和哈希、每组样本数及三轮记录。没有 GPU 内部遥测时明确只报告客户端性能。
