## 设计与计量

复用阶段 1 固定版本的 ChartQA 清洗测试集。按 human 和 augmented 等额抽取，每个子集选 16 题，两者合计 32 个不同图表。每个子集按原图面积分层，分别从 ≤ 602,112、602,112 至 1,003,520（左开右闭）、> 1,003,520 像素抽取 9、6、1 题。先从最大面积层抽样，层内按固定种子与样本 ID 的 SHA-256 排序，按图像哈希去重。分层配置提高大图覆盖，样本分布有意偏离全量测试集。

固定模型、服务和问题提示。四档共用同一批图片和题目。配置档位为原图尺寸、低档 200,704、中档 602,112、高档 1,003,520 像素，名义上对应 256、768、1,280 个合并后 Token 的面积预算。每档仅缩小超上限图像，统一方向校正、RGB 和 PNG 编码。模型处理器仍按网格调整尺寸，实测值取服务端 `image_grid_thw`、合并系数、占位符区间和实际图像占位符的交叉核对结果。

RTX 5090 单卡、BF16 基座、SGLang 0.5.23、请求并发 1。服务关闭 Radix Cache，预处理缓存大小为 0。进行 3 轮，每轮按固定种子打乱档位顺序，使用同一题目顺序配对比较。每轮每档先用每个子集的最大图各发送 1 条预热请求，再发送 32 条计量请求。每个档位共 96 条计量请求，全程共 384 条计量和 24 条预热请求。

TTFT 从同机客户端发起 SSE 请求计到收到首个非空文本事件，包含请求序列化、服务排队、视觉处理和首个输出的等待。图像预处理在发请求前完成。报告 P50 和 P90，预热请求排除在分位数和分数之外。

沿用阶段 1 的 ChartQA relaxed accuracy。字符串去首尾空白并忽略大小写，数值答案接受 5% 相对误差，带百分号的值先除以 100。直接对模型短答评分，保留原始输出。请求失败计错并单列，截断也单列。每轮使用相同 32 道题，准确率和计数反映这个固定样本。[ChartQA 论文](https://aclanthology.org/2022.findings-acl.177/)

## 复现

按[部署说明](DEPLOYMENT_SMOKE.md)运行同样的服务和观测钩子。使用已经校验的阶段 1 `data/processed/ablation/test.jsonl` 和相邻 `images/`。如需重建输入，运行[阶段 1 数据准备](../../phase1-assistant/docs/ABLATION.md)中的下载与清洗命令，阶段 2 无需运行训练或全量推理。脚本验证输入 JSONL 和样本图像的 SHA-256，并通过 `/server_info` 检查服务配置。

```bash
# 从总仓库根目录进入。在 SGLang 服务所在机器执行。
cd 02-Multimodal/phase2-sglang
export PHASE1_DIR="$(cd ../phase1-assistant && pwd)"
# 分开部署时，将 PHASE1_DIR 改为阶段 1 项目绝对路径。
PYTHONPATH="$PWD/.runtime:$PWD:$PHASE1_DIR" python3.12 -m benchmark.chartqa_budget_pilot \
  --dataset "$PHASE1_DIR/data/processed/ablation/test.jsonl" \
  --config configs/chartqa-budget-pilot.json \
  --trace results/server/vision.jsonl \
  --output "results/chartqa-pilot-$(date -u +%Y%m%dT%H%M%SZ)"
```

输出包含样本与调度清单、逐请求 SSE 结果及服务端 Trace、分组与逐轮汇总。每次用新输出目录保留原记录。
