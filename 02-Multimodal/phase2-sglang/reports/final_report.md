**Design of a Multimodal Visual Question Answering System and Optimization of Visual Token Budgets Based on SGLang**

## 摘要

多模态视觉语言模型将图像编码为视觉表示，并与文本指令共同参与自回归生成。视觉输入细节会影响问答质量，也会改变编码、Prefill、缓存占用与服务排队成本。本项目围绕 Qwen2.5-VL-7B-Instruct 和 SGLang 构建视觉语言助手，编写多轮会话、图像预算、流式客户端与自动评测链路。预算策略包括保留默认处理、固定像素上限和基于问题词与图像元信息的自适应选择。实验设计考察图像数量、请求并发和预算对延迟、吞吐及质量的作用。单卡部署已通过单图与双图请求的功能验证，服务端观测分别记录到 2,691 与 5,382 个视觉 Token。预算优化的速度和质量影响待正式实验评估。

关键词：视觉问答；SGLang；Qwen2.5-VL；视觉输入预算；推理系统。

## 1 研究背景与意义

图像问答不仅要求识别物体，还涉及文字读取、空间关系、图表与文档结构。在服务系统中，提高输入分辨率可能保留细节，同时增加视觉编码与语言输入处理成本。对有限 GPU 资源而言，应研究不同任务对视觉细节的需求，而非一律降低分辨率或默认使用最高分辨率。本项目不训练模型，重点是构建服务并制定可验证的质量—效率评测方法。

RQ1：视觉输入规模如何影响客户端 TTFT、E2E、输出吞吐和显存？RQ2：规则预算能否在约束质量下降的情况下改善效率？RQ3：重复图像与多轮交互的缓存是否带来收益？前两项为核心，RQ3 为扩展。

## 2 相关技术

Qwen2.5-VL 技术报告介绍动态视觉输入和图像/文档理解能力 [1]；模型卡公开 7B 模型与使用方式 [2]。SGLang 提供推理运行时与 OpenAI-compatible 服务接口，官方支持列表列出 Qwen-VL [3]。支持列表是兼容性线索，不是本项目环境启动成功的证据。

图像预算不能简单等于模型视觉 Token。公开处理器配置包括 14 像素 patch 与 2 倍空间合并 [4]，实际 Token 数还依赖输入调整、网格与帧组织。本项目使用像素预算命名，只有接入实际处理器遥测后才报告视觉 Token。

VQAv2、TextVQA 和 DocVQA 分别覆盖通用图像问题、场景文字和文档问答。三类任务评分定义不同，不应把 EM、VQA consensus 与 ANLS 当作同一准确率无条件平均。

## 3 系统架构与实现

输入经 Pillow 解码、方向校正和 RGB 转换，预算模块按需要保持宽高比缩小；PNG 编码后通过 OpenAI 图像消息提交 SGLang。模型内部执行视觉编码、投影以及语言 Prefill/Decode，客户端解析 SSE 并向 Gradio 返回文本、耗时和 usage。

模块对应如下：frontend 管理会话与用户输入；api 管理连接与 SSE；preprocessing 控制图片预算；benchmark 执行请求并发、预热和重复；evaluation 计算质量；analysis 汇总分位数与图表。界面保存成功回合，异常不污染历史，清空操作同时清除模型上下文。

本实现首轮要求图像，后续可只输入追问，也可加入新图。文件上限 25 MiB、解码后上限 4000 万像素，每轮最多 8 张图，总会话最多 10 轮。长上下文可能在轮数上限前触发服务端长度限制，当前通过异常提示处理，不自动截断历史。生产级身份验证、配额和多人隔离不属于当前课程 MVP。

## 4 视觉预算优化方法

Baseline 不主动缩小图片，仍执行统一解码和 PNG 编码。Low、Medium、High 的像素上限分别是 200704、602112、1003520。预算选择后，缩放因子为 sqrt(B/(W×H))，仅当图像超过预算时缩小，不放大低分辨率输入。

Adaptive 使用可解释规则：问题出现文字、文档、图表、OCR 等词，或图片为高度超过 1600 像素且纵横比大于 1.35 的纵向输入时选择 High，否则选择 Low。该规则没有学习参数，不读取参考答案或任务标签。其元信息检查与图像处理开销统一计入 preprocessing_s，但问题词提取也可能偏向具体提示形式，需在不同措辞下分析鲁棒性。

该方法属于客户端输入预算控制，不是视觉 Token 剪枝、编码器内部 early exit 或 SGLang kernel 优化。实际收益取决于服务端二次 resize 和动态网格；若默认图像本就很小，预算策略可能没有作用。

## 5 实验设计

实验前固定模型 commit、SGLang 发行版本、CUDA/PyTorch、精度、GPU 与服务参数。采集服务日志、pip freeze、nvidia-smi 与项目 commit。每种任务使用独立的固定样本集和参考答案，抽样种子为 20261111，并记录源数据及图片 SHA256。

### 5.1 实验 A：输入规模与服务负载

图数 1/2/4/8，预算 Low/Medium/High，客户端并发 1/4/8/16，输出上限 128、temperature=0。Baseline/Adaptive 同样可运行以提供参照。每组预热 3 次并至少重复 3 轮，配置顺序按固定种子打乱。并发是同时存在的客户端请求数，不能当作运行时内部 batch size。

多图需要真实多图样本及有效标注；缺少该图数的样本时记录 skipped，不通过复制图片补齐。失败请求计入成功率，质量仅对成功请求计算，并同时报告失败率，以防产生幸存者偏差。预热失败终止该次运行，先解决部署问题。

### 5.2 实验 B：预算与质量权衡

在相同任务和样本上比较 Baseline、Low 与 Adaptive；Medium/High 用于细化预算曲线。分别报告各任务质量、客户端延迟和吞吐。可接受损失在观察结果前预注册：建议绝对质量损失不超过 0.02，再在满足该约束的配置中比较延迟；该阈值是课程实验选择，不是已观察结论。

后续可对相同样本的成对质量差和每轮时延做 bootstrap 置信区间。当前分析器提供描述性分位数，不内置显著性检验。不能仅凭小样本均值宣布改进。

### 5.3 指标定义与可观测性

TTFT 为请求开始至首个非空 SSE 内容；E2E 为至完成事件；TPOT 为首末内容时间差除以真实 usage 输出 Token 数减一，仅在可计算时报告。SSE 事件不一定逐 Token，因此 TPOT 是客户端估计。内部 Prefill、Vision Encoder 与 Decode kernel 时间需要 profiler，客户端 TTFT 不能替代。

输出吞吐按组内成功输出 Token 数除以墙钟时间计算，失败等待保留在分母。设备显存通过独立的 nvidia-smi 采样器记录，包括同 GPU 其他进程，采样最大值不是 allocator 峰值。显存对比应在独立 GPU 上按实验组分开采集，扣除或同时报告空闲服务基线，不把全程总峰值归因于某一预算。

部署冒烟已按请求 ID 将处理器的 `image_grid_thw`、`spatial_merge_size` 和实际图像占位符与 API 回包关联。正式实验记录的 `visual_tokens_actual` 仍须接入同一观测路径。[部署验收](DEPLOYMENT_SMOKE.md)

### 5.4 缓存扩展

区分预处理缓存、视觉特征缓存和语言 Prefix/KV 缓存。Warm 表示未主动清缓存，不等于命中；Cold 调用服务 flush 接口并要求并发=1，仍需确认该固定版本 API 清除范围。RQ3 后续用重复图像与不同问题比较缓存阶段遥测，不能仅用延迟下降推断视觉特征已复用。目前未实现新缓存机制。

## 6 实验结果与分析

| 证据项 | 当前状态 | 可得结论 |
|---|---|---|
| 阶段 2 Gradio、多轮与文档交互 | 待验证 | 本次使用流式 API 验收 |
| CPU 单元测试 | 9 项通过 | 覆盖已有客户端、预算、分析和评分用例 |
| SGLang 7B BF16 启动 | 单卡通过 | 单图读数与双图差值正确 |
| RQ1 性能 | 128 道单图题、单并发 | 原图、低、中、高、自适应均已测 TTFT，图数与并发扩展待测 |
| RQ2 质量与效率 | 同题配对，重复 3 轮 | 自适应相对原图的 TTFT P50 从 97.2 降到 62.7 ms，正确数从 109 降至 99 |
| 视觉 Token | 静态图已逐请求核对 | 原图、低、中、高、自适应均值为 618.0、241.2、581.2、612.8、255.3 |
| GPU 预算组显存 | 待测 | 按实验组采样 |

同一批 128 题复测加入中档路由后，改进规则较旧规则正确数从 99 增至 105，TTFT P50 从 62.6 ms 增至 63.6 ms，P90 从 65.1 ms 增至 102.1 ms。固定中档答对 109 题，其平均实际视觉 Token 为 581.2，改进规则为 340.8。[三组对照](CHARTQA_ADAPTIVE_V2.md)

规则冻结后，从同一 ChartQA test 导出抽取 128 张与开发集图像不重叠的图。改进规则答对 108 题，旧规则答对 104 题，固定中档答对 113 题。改进规则相对固定中档平均少用 43.9% 视觉 Token，TTFT P50 为 62.6 ms，固定中档为 96.9 ms。[独立图像留出集](CHARTQA_ADAPTIVE_HOLDOUT.md)

排除开发集和留出集后，剩余 3 张达高档门槛图覆盖 4 题，三种策略均答对 3 题。改进规则在这组平均用 1,273.5 个视觉 Token，固定中档为 769.5。在 5 道近门槛题上，固定高档相对改进规则多得 1 分，差异来自百分号格式。[高档长图专项](CHARTQA_ADAPTIVE_HIGH_BRANCH.md)

正式矩阵待固定样本和指标后执行。报告终稿需要补充每组样本数、失败率、长度截断比例、延迟分位数、各任务质量与显存采样口径，并附对应原始记录。

错误分析应对比 OCR 小字、计数、空间关系、图表坐标等失败样本，分别记录 Baseline 与预算策略输出；若 Adaptive 对文档误分 Low，应追踪元信息和提示词规则。延迟上升可能来自 PNG 传输、排队、缓存状态或处理器开销，不应直接归因于模型计算。

## 7 功能验证与演示流程

固定环境、CPU 测试、单卡启动、单图读数和双图差值已完成。待覆盖单图描述、同图追问、文档读取、空问题、损坏图片与服务断连的错误处理，再进入小型基准和完整实验。

## 8 局限与未来工作

当前质量和时延结果来自 128 题、单图、单并发的 ChartQA 分层样本，其中较大图表占比高于原测试集。自适应规则给 125 道题分配低档，对输出格式及图表推理难度的识别有限。客户端像素上限还会受到处理器网格对齐影响。后续把服务端观测接入正式矩阵，补齐任务分层统计、bootstrap 区间和 profiler 分解。

## 9 结论

本阶段已验证单张 RTX 5090 上的静态图推理和服务端视觉 Token 计量。在 128 题上，中档保持原图正确数，自适应以接近低档的 TTFT 多答对 1 题。更大规模和并发下的质量与效率待正式实验量化。
